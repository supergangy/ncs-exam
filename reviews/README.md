# reviews — 필기후기 기반 최신 출제유형 DB

공준모 같은 취업 커뮤니티의 **필기후기** 글을 기관별로 쌓아, 실제 시행 시험의 최근 출제 경향을
뽑아내는 도구다. 결과는 [`../docs/RECENT_TRENDS.md`](../docs/RECENT_TRENDS.md) 에 정리된다.

## 왜 필요한가

지금 각 회차의 `PROFILE`(세트 비율·각주 개수·지문 길이)은 전부 **시판 봉투모의고사** 실측이다.
`docs/CORPUS_ANALYSIS.md` 0절에 신뢰도 등급을 매겨 둔 이유가 그것이다 — 시판본은 실제 시험의
근사치일 뿐이다.

필기후기는 **실제 시행된 시험**의 정보다. 급이 다르다. 후기가 쌓이면
`rounds/<회차>/config.py` 의 `PROFILE` 과 소재 후보를 실제 경향으로 교정할 수 있다.

## 수집 방법 — 붙여넣기다, 크롤링이 아니다

네이버 카페는 로그인·등업이 있어야 글이 보이고, 이용약관이 자동 수집을 금지한다.
**로그인 세션으로 글을 긁어오는 크롤러는 이 저장소에 두지 않는다.**

대신 본인이 이미 볼 수 있는 글을 복사해 넣으면 도구가 그걸 파싱한다.
클립보드에서 바로 받을 수 있어 실제로 번거롭지 않다.

```bash
# 후기 글을 복사한 뒤
python reviews/ingest.py --clip --org 건보

# 또는 파일로
python reviews/ingest.py reviews/raw/건보/2026-03-15.txt --org 건보
```

## 저작권 경계

`corpus/` 와 같은 원칙이다. **원문은 로컬에만, 파생 데이터만 커밋한다.**

| 대상 | 커밋 | 이유 |
|---|---|---|
| `raw/<기관>/*.txt` — 후기 원문 | **제외** | 작성자 저작물. `.gitignore` 로 차단 |
| `db.json` — 추출한 항목 | 커밋 | 기관·날짜·영역·유형·소재 키워드 등 사실 정보 |
| `ingest.py` · `report.py` | 커밋 | 우리가 작성한 도구 |
| `docs/RECENT_TRENDS.md` | 커밋 | 집계·경향 분석 |

`db.json` 에는 **원문 문장을 통째로 담지 않는다.** 소재 키워드와 분류 결과만 남긴다.
후기 작성자를 식별할 수 있는 정보(닉네임·아이디)도 담지 않는다.

## 추출 항목

| 항목 | 예 |
|---|---|
| `org` · `date` · `track` | 건보 / 2026-03-15 / 행정직 |
| `structure` | 60문항 60분, 의사소통·수리·문제해결 |
| `topics` | 장기요양보험 등급판정, 본인부담상한제, 진료비 추이 |
| `types` | 자료해석, 조건추리, 모듈 |
| `difficulty` · `time_pressure` | 체감 중상 / 시간 매우 부족 |
| `notes` | 모듈 비중 증가, 신유형 등장 |

날짜·문항수·영역명·시간은 정규식으로 잡는다. 소재와 유형은 `LEXICON` 사전 매칭이고,
**매칭되지 않은 후보 어절을 따로 보여 주므로** 사전을 키워 가며 정확도를 올린다.

## 보고서

```bash
python reviews/report.py --org 건보 --md > docs/RECENT_TRENDS.md
```

기관별로 최근 시행분부터 정렬해 소재 빈도·유형 분포·체감 난이도를 집계한다.
후기는 주관적 기억이므로 **표본 수를 함께 표시**한다. 후기 2건짜리 경향은 경향이 아니다.
