# reviews — 필기후기 기반 최신 출제유형 DB

공준모 같은 취업 커뮤니티의 **필기후기** 글을 기관별로 쌓아, 실제 시행 시험의 최근 출제 경향을
뽑아내는 도구다. 결과는 [`../docs/RECENT_TRENDS.md`](../docs/RECENT_TRENDS.md) 에 정리된다.

## 왜 필요한가

지금 각 회차의 `PROFILE`(세트 비율·각주 개수·지문 길이)은 전부 **시판 봉투모의고사** 실측이다.
`docs/CORPUS_ANALYSIS.md` 0절에 신뢰도 등급을 매겨 둔 이유가 그것이다 — 시판본은 실제 시험의
근사치일 뿐이다.

필기후기는 **실제 시행된 시험**의 정보다. 급이 다르다. 후기가 쌓이면
`rounds/<회차>/config.py` 의 `PROFILE` 과 소재 후보를 실제 경향으로 교정할 수 있다.

## 사용법

### 1. 수집기를 띄운다

```bash
python reviews/serve.py --org 건보 --open
```

`--open` 을 주면 설치 페이지(`http://127.0.0.1:8765`)가 바로 열린다.
**초록색 「후기 담기」 버튼을 즐겨찾기 바로 끌어다 놓는다. 최초 한 번만 하면 된다.**
붙여넣기가 아니라 드래그다 — 브라우저에 따라 주소창 붙여넣기는 `javascript:` 를 지운다.

### 2. 후기 글을 열고 즐겨찾기를 누른다

그게 전부다. 알림창에 적재 결과가 뜨고 수집기 콘솔에도 한 줄 남는다.

```
[적재] 건보 2026-03-15 · 유형 내용일치, 추론, 자료해석, 규정적용, 조건추리
       · 소재 장기요양보험, 보장성 강화, 진료비, 본인부담, 요양급여 · 난이도 상
```

같은 글을 두 번 눌러도 지문(fingerprint)으로 걸러진다.
**기관은 수집기가 정한다.** 다른 기관을 모을 때는 수집기만 다시 띄우면 되고 즐겨찾기는 그대로 쓴다.

```bash
python reviews/serve.py --org 한전
```

### 3. 집계한다

```bash
python reviews/report.py --org 국민건강보험공단
python reviews/report.py --md > docs/RECENT_TRENDS.md
```

### 파서를 고쳤으면 — `--rebuild`

```bash
python reviews/ingest.py --rebuild
```

`raw/` 의 원문을 **전부 다시 파싱해 `db.json` 을 새로 만든다.**
사전을 키웠거나 파서를 고쳤을 때, 기관명 표기를 바꾸고 싶을 때 이걸 돌린다.
원문을 남겨 두는 이유가 이것이다 — 분류는 언제든 다시 할 수 있다.

기관명은 후기 양식의 `▷ 기관명` 을 읽어 `lexicon.py` 의 `ORG_ALIASES` 로 정규화한다.
「건보」 「건강보험공단」 「국민건강보험공단」이 모두 한 기관으로 접히고,
`raw/` 하위 폴더도 정식명으로 정리된다. 수집기에 넘긴 `--org` 는 양식에 기관명이 없을 때의 폴백이다.

## 후기 양식을 우선 읽는다

공준모 후기는 대개 정형 양식으로 시작한다.

```
▷ 기관명 : 국민건강보험공단
▷ 직렬명 : 요양직
▷ 시험과목 : ncs + 장기요양보험법
▷ 시험시간 : 60분/ 30분
▷ 난이도 : 중상
```

자유서술을 정규식으로 훑는 것보다 이쪽이 훨씬 정확하므로 **양식 값을 우선**한다.
난이도는 `중~중상` 처럼 범위로 적히기도 하는데, 그때는 강한 쪽을 택한다.
시험시간이 `60+20` 처럼 붙어 나오면 앞의 것이 NCS다.

### 브라우저를 쓰지 않을 때

본문을 복사한 뒤 클립보드에서 받아도 된다.

```bash
python reviews/ingest.py --clip --org 건보
python reviews/ingest.py --clip --org 건보 --dry    # 저장하지 않고 결과만
python reviews/ingest.py 후기.txt --org 건보         # 파일에서
```

## 크롤러를 두지 않는 이유

네이버 카페는 로그인·등업이 있어야 글이 보이고, 이용약관이 자동 수집을 금지한다.
로그인 자동화는 계정 비밀번호를 다루는 일이 된다.
**로그인 세션으로 글을 긁어오는 크롤러는 이 저장소에 두지 않는다.**

실용적인 이유도 있다. 카페 본문은 `iframe#cafe_main` 안에 동적 렌더링되고 공개 읽기 API가 없으며
봇 탐지가 수시로 바뀐다. 만들어도 오래 못 간다.

위의 북마클릿 방식은 **이미 로그인된 브라우저에서 이미 열려 있는 페이지의 본문을 읽을 뿐**이다.
로그인 자동화도 봇 우회도 없고, 글당 클릭 한 번이라 체감 차이가 크지 않다.

## 저작권 경계

`corpus/` 와 같은 원칙이다. **원문은 로컬에만, 파생 데이터만 커밋한다.**

| 대상 | 커밋 | 이유 |
|---|---|---|
| `raw/<기관>/*.txt` — 후기 원문 | **제외** | 작성자 저작물. `.gitignore` 로 차단 |
| `db.json` — 추출한 항목 | 커밋 | 기관·날짜·영역·유형·소재 키워드 등 사실 정보 |
| `ingest.py` · `report.py` | 커밋 | 우리가 작성한 도구 |
| `docs/RECENT_TRENDS.md` | 커밋 | 집계·경향 분석 |

`db.json` 에는 **원문 문장을 통째로 담지 않는다.** 소재 키워드와 분류 결과만 남긴다.
후기 작성자를 식별할 수 있는 정보(닉네임·아이디)도 담지 않는다.

## 추출 항목

| 항목 | 예 |
|---|---|
| `org` · `date` · `track` | 건보 / 2026-03-15 / 행정직 |
| `structure` | 60문항 60분, 의사소통·수리·문제해결 |
| `topics` | 장기요양보험 등급판정, 본인부담상한제, 진료비 추이 |
| `types` | 자료해석, 조건추리, 모듈 |
| `difficulty` · `time_pressure` | 체감 중상 / 시간 매우 부족 |
| `notes` | 모듈 비중 증가, 신유형 등장 |

날짜·문항수·영역명·시간은 정규식으로 잡는다. 소재와 유형은 `LEXICON` 사전 매칭이고,
**매칭되지 않은 후보 어절을 따로 보여 주므로** 사전을 키워 가며 정확도를 올린다.

## 보고서

```bash
python reviews/report.py --org 건보 --md > docs/RECENT_TRENDS.md
```

기관별로 최근 시행분부터 정렬해 소재 빈도·유형 분포·체감 난이도를 집계한다.
후기는 주관적 기억이므로 **표본 수를 함께 표시**한다. 후기 2건짜리 경향은 경향이 아니다.
