## 2. 본문 분량 실측 (발문 + 자료, 공백 포함)

세트 공유 지문은 소속 문항 전체에 합산했다.

| 영역 | 건보(피듈) 중앙값 | 한전(피셋) 중앙값 | 건보 하위25%~상위25% |
|---|---|---|---|
| 의사소통 | 1,097자 | 1,354자 | 36 ~ 1,572 |
| 수리 | **707자** | 806자 | 325 ~ 973 |
| 문제해결 | **1,553자** | 1,463자 | 211 ~ 1,998 |
| 자원관리 | – | 1,045자 | – |
| 정보 | – | 1,141자 | – |

**핵심 관찰**

1. **수리는 짧고 문제해결은 길다.** 수리 중앙값 707자 vs 문제해결 1,553자로 2배 이상 차이. 수리는 표 위주라 산문이 적고, 문제해결은 규정·안내문을 통째로 읽혀야 한다.
2. **분량 편차가 크다.** 건보 의사소통의 하위 25%가 36자다. 세트 두 번째 문항처럼 지문을 공유하고 발문만 있는 경우가 많다는 뜻이다. **모든 문항을 균일한 길이로 만들면 오히려 시판본과 달라진다.**
3. 피셋형이 피듈형보다 전반적으로 길다(의사소통 +257자). 자료를 더 많이 읽히는 구조다.

## 3. 세트문항 비율 — 시판본의 핵심 구조

| 영역 | 건보(피듈) | 한전(피셋) |
|---|---|---|
| 의사소통 | 53% | 30% |
| 수리 | **73%** | 57% |
| 문제해결 | 67% | 59% |
| 자원관리 | – | 65% |
| 정보 | – | 56% |

**시판본은 절반 이상이 세트문항이다.** 특히 건보 수리는 73%로, 자료 하나에 문항 2~3개를 매다는 것이 기본형이다.

정형 구조는 `자료 1개 → ① 이해·판단 문항 + ② 계산·적용 문항`이다. 첫 문항에서 자료를 읽히고, 둘째 문항에서 그 이해를 계산이나 사례 적용으로 확장한다.

> **우리 시험 현황**: 7세트 14문항(28%)으로 설계했으나 실제 시판본의 절반 수준이다. 60분 압축과 8영역 분산 때문에 불가피한 측면이 있으나, **3차 이후 세트 비중을 높이는 편이 시판본에 가깝다.**

## 4. 자료 구조 사용률

| 요소 | 건보(피듈) | 한전(피셋) |
|---|---|---|
| 표 | 수리 26% · 문제해결 8% · 의사소통 3% | 자원관리 24% · 수리 일부 |
| 그래프 | 수리 13% | 수리 21% |
| `<보기>` | 문제해결 24% · 수리 16% · 의사소통 9% | **정보 44%** · 수리 36% · 문제해결 29% |
| `<조건>`/`<정보>` | 문제해결 5% · 수리 2% | 문제해결 18% |
| 각주 `※` | 회차당 3.4개 | **회차당 8.0개** |

**핵심 관찰**

1. **`<보기>` ㄱㄴㄷㄹ 조합형이 전 영역에 퍼져 있다.** 수리·문제해결뿐 아니라 정보(44%)·의사소통(9%)에도 쓰인다. 우리 시험은 20문항 중 4건(50문항 환산 10건)으로 목표 12~14건에 미달한다.
2. **각주는 피셋형에서 2배 이상 많다**(8.0 vs 3.4). 계산식 정의·범위 한정·예외 규정을 각주에 숨기는 것이 피셋형 난이도의 핵심 장치다.
3. 그래프는 수리에 집중(13~21%). 다른 영역에는 거의 없다.

## 5. 발문 문형 사전

### 5-1. 기관별 어투 차이 (중요)

| | 건보(피듈) | 한전(피셋) |
|---|---|---|
| 지배적 어미 | **`~을 고르면?`** | **`~것은?`** |
| 예 | 위 자료에 대한 설명으로 옳지 않은 것을 **고르면?** | 이에 대한 설명으로 옳지 않은 **것은?** |

기관색을 맞추려면 어미부터 통일해야 한다. 섞어 쓰면 어느 쪽도 아닌 인상이 된다.

### 5-2. 건보 1~8회 빈출 말미 문형 (423문항)

| 빈도 | 문형 |
|---|---|
| 25 | 위 자료에 대한 설명으로 옳지 않은 것을 고르면 |
| 10 | 주어진 자료에 대한 설명으로 옳지 않은 것을 고르면 |
| 9 | 위 자료에 대한 설명으로 옳은 것을 고르면 |
| 7 | 위 자료에 대한 설명으로 옳지 않은 것은 |
| 6 | 대한 설명으로 옳은 것을 `<보기>`에서 모두 고르면 |
| 4 | 안내문에 대한 설명으로 옳지 않은 것을 고르면 |
| 4 | 읽고 보인 반응으로 적절하지 않은 것을 고르면 |
| 3 | 글의 흐름상 삭제되어야 할 문장을 고르면 |
| 3 | 위 보도자료의 제목으로 가장 적절한 것은 |
| 2 | 윗글의 표제와 부제로 가장 적절한 것은 |
| 2 | 주어진 글에서 알 수 없는 내용을 고르면 |

전체 423문항에 **서로 다른 발문 326종** — 같은 문형을 반복하지 않으려는 설계가 뚜렷하다. 전체 목록은 `corpus/parsed/발문사전_건보1-8.md`(로컬).

### 5-3. 유형 분포 (건보 423문항)

| 유형 | 비중 | 유형 | 비중 |
|---|---|---|---|
| 옳지 않은 것 | 28.8% | 주제·중심내용 | 3.5% |
| 옳은 것 | 17.3% | 빈칸 | 3.1% |
| 일치/불일치 | 5.0% | 추론 | 1.9% |
| `<보기>` 조합 | 4.7% | 인물 판단 | 1.7% |
| 계산 일반 | 4.7% | 문장 삭제 / 문단 배열 | 각 1.4% |

**`옳지 않은 것`이 `옳은 것`보다 1.7배 많다.** 오답 4개를 모두 참으로 만들어야 하므로 자료를 촘촘히 읽히는 효과가 있다.

영역별 특징:
- **의사소통** — 진위 판정(42%) 외에 주제·중심내용 10%, 빈칸 8%, 문장삭제 4%, 문단배열 등 **조작형 발문이 다양하다.**
- **수리** — 옳지 않은 것 35%가 압도적. 계산 일반 12%, 보기조합 8%, 순서비교·빈칸수치 각 4%.
- **문제해결** — 진위 판정 50%, 보기조합 5%, 인물 판단 5%.

## 7. 재현 방법

```bash
# 1) PDF → 페이지 덤프
python -c "from pypdf import PdfReader; ..."   # corpus/raw/*.txt 생성

# 2) 회차·문항 분해 및 통계
python corpus/analyze.py corpus/raw/pidule_1-8_ocr.txt --label "건보 1~8회 피듈형" --areas 20,20,20
python corpus/analyze.py corpus/raw/pset_kepco_9-10.txt --label "한전 9~10회 피셋형" \
       --areas 10,10,10,10,10 --names "의사소통,수리,문제해결,자원관리,정보"
```

`corpus/analyze.py` 구현 요점:
- **문항 경계는 최장증가부분수열(LIS)로 복원한다.** OCR이 번호를 놓쳐도 뒤쪽 문항이 통째로 유실되지 않는다. 순차 매칭으로는 인식률 19%였던 것이 LIS로 88%가 되었다.
- OCR이 꺾쇠를 `〈〉＜＞《》［］` 로 흩뿌리므로 전부 `<>`로 접어서 판정한다.
- 조사·어미 오인식(`을→올/율`, `를→룰/롤`, `절→잘`)을 흡수하는 `fuzzy()`를 분류에만 적용한다.

## 8. OCR 한계 — 반드시 감안할 것

알PDF OCR 기준 실측:

| 대상 | 정확도 | 판단 |
|---|---|---|
| 산문(지문·발문) | 오탈자 1~3%, 주로 조사 혼동 | **통계·패턴 분석에 지장 없음** |
| 표 안의 숫자 | 심각하게 깨짐 (`而，000관`, `12,00◦관`, `6/卜9/30`) | **수치는 절대 신뢰 금지** |
| 기호(`※`, 원문자) | `*`, `씨`, `X`로 오인식 빈번 | 정규화 후에도 과소 집계 가능 |

따라서 **이 문서의 분량·비율·문형 통계는 신뢰할 수 있으나, 개별 문항의 수치 자료를 인용할 때는 원본 이미지로 대조해야 한다.**

각주 집계(건보 3.4개/회차)는 OCR 손실로 실제보다 낮게 잡혔을 가능성이 있다. 한전본(원본 텍스트, 8.0개/회차)이 더 정확한 값이다.
