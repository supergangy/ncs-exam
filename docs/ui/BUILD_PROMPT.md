# Build 입력 — 화면별 지시문

Google AI Studio **Build** 에 넣을 프롬프트다. 도면 3장과 짝을 이룬다.

## 왜 지시문이 따로 있나

그림만 넣으면 모델이 빈칸을 자유롭게 채운다. 2026년 지침이 한 점에서 일치한다 —
와이어프레임은 **UI 컴포넌트·접근성·동작을 명시**해야 하고, 입력·토글·결과·로직에
각각 주석이 있어야 한다.

특히 위험한 것은 **로직을 새로 짜는 것**이다. 채점·복습 간격·검색은 이미
`web/src/core/` 에 있고 764문항으로 검증했다. Build 가 자기 식으로 다시 짜면
겉으로는 도는데 답이 틀리거나 복습이 안 뜬다. 그래서 매 화면에
「로직을 만들지 마라」를 못 박는다.

## 절대 어기면 안 되는 것 — 이것이 다시 만드는 이유다

## 접는 순서 — 이 차례를 지켜라

    1순위  좌 내비  → 햄버거 서랍. 문항을 읽는 데 없어도 된다
    2순위  번호판   → 바텀시트. 이동은 위쪽 ◀ ▶ 로 대신한다
    3순위  **문항 본문은 마지막까지 지킨다.**
           최소 폭 560px 아래로는 글자 크기만 줄이고 접지 않는다

## 태블릿 768~1279 — 2단

- 머리말에 햄버거(≡). 누르면 좌 내비가 서랍으로 왼쪽에서 나온다
- 번호판은 **남긴다.** 4열 격자로 좁힌다
- 제출 버튼은 번호판 안에 그대로 있다

## 모바일 < 768 — 1단

- 머리말 아래에 이동 바 — `◀   12 / 40   ▶` 와 「번호판 열기」
- 선지는 화면 폭을 꽉 채운다. 높이 44px 를 지킨다
- 발문은 18px 까지만 줄인다. 그 아래로 내리지 마라
- 자료 표는 「가로 스크롤 →」 안내와 함께 스크롤한다
- 하단 탭 5개 — **화면에 고정되는 유일한 요소다**

## 바텀시트 — 여기가 결함을 없애는 자리다

번호판을 시트로 올린다. **제출 버튼을 시트 안에** 둔다.
그러면 하단 탭과 겹칠 수 없다.

    손잡이 막대 (44×5, --line)

## 받은 뒤 할 일

Build 결과를 그대로 쓰지 않는다. 세 가지를 확인한다.

| 무엇 | 어떻게 |
|---|---|
| 로직을 새로 짰나 | `grep -rn "2.5\|86400000\|\.an ===" src/ui/` — `core/` 밖에 있으면 걷어낸다 |
| fixed 를 남겼나 | `grep -rn "position:\s*fixed" src/` — 하단 탭과 시트 둘뿐이어야 한다 |
| 토큰을 안 쓰고 색을 박았나 | `grep -rnE "#[0-9a-f]{6}" src/ui/` — `tokens.css` 밖이면 고친다 |

그다음 `npm test` (25건) 가 그대로 통과하는지 본다. 통과해야
로직을 건드리지 않았다는 뜻이다.
