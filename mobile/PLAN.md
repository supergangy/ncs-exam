# 앱 기능 확장 계획 — PSAT 앱 분석에서 가져올 것

> 2026-08-15. `com.psatpractice.app` v2.0.0(Flutter, split APK 29.5MB)을 뜯어 보고
> 우리 앱(`mobile/` v1.5.1)에 옮길 것을 골랐다. 2판 — 사용자 판단을 반영했다.
>
> **바뀐 것**: 학습 달력·연속일은 뺀다 · 저장소를 CRUD로 바꾸는 것을 넣는다 ·
> 수익화는 보류한다(사유는 §4).

## 0. 분석한 앱

5급·민경채 PSAT 기출 앱이다. **같은 Flutter** 스택이라 코드 수준에서 비교가 된다.

| | PSAT 앱 | 우리 앱 |
|---|---|---|
| 콘텐츠 | 원본 기출 PDF 133개를 R2에서 내려받는다 | 재조판한 `bank.json` 1MB를 앱에 넣는다 |
| 문항 단위 | `exam_page_mapping.json`(747KB)이 PDF를 문항별로 자른다 | 문항이 애초에 낱개 데이터다 |
| 필기 | 연필·형광펜·지우개 (`perfect_freehand`) | 없다 |
| 저장 | `sqflite` + `shared_preferences` | `shared_preferences` **한 칸** |
| 알림 | 로컬 알림 + 정확 알람 | 없다 |
| 통계 | `fl_chart` · Syncfusion · `table_calendar` | 텍스트 위주 |
| 수익 | 광고(AdMob + Meta 미디에이션) · 구독(RevenueCat) | 없다 |
| 백엔드 | Firebase 4종 · Cloud Functions · R2 | **없다** |
| 의존성 | 246개 | 12개 |

### 핵심 장치 — `contentBounds`

```json
{ "questionNumber": 2,
  "contentBounds": [ { "pdfPage": 1, "x": 0.0, "y": 37.98,
                       "width": 701.01, "height": 672.04 } ] }
```

문항 하나가 PDF 어느 페이지의 어느 사각형인지 적어 둔 표다. 배열인 것은
**한 문항이 두 면에 걸칠 때** 조각이 여럿이기 때문이다. 이 표 하나로 PDF가
문항 단위 앱이 된다.

## 1. 실현 가능성을 가르는 것 — 좌표계

우리 앱은 문항을 `flutter_html` 로 그린다. **높이가 그때그때 달라진다** —
글꼴 크기, 화면 폭, 표 줄바꿈에 따라 같은 문항이 다른 높이로 뜬다.
필기를 그 위에 얹으면 **다음에 열 때 획이 딴 데 찍힌다.**

| 갈래 | 방법 | 값 |
|---|---|---|
| (a) 정규화 | 폭 기준 0~1 로 저장하고 다시 그릴 때 스케일 | 줄바꿈이 달라지면 대책이 없다 |
| (b) 이미지 고정 | 문항을 한 번 그려 이미지로 굳히고 그 위에 필기 | 확실하나 글자 확대·다크모드에서 다시 구워야 하고 텍스트 선택이 죽는다 |
| (c) **PDF 회차 모드** | 회차는 PDF로 보여 주고 거기에만 필기 | **좌표 문제가 사라진다.** 인쇄본과 화면이 같아지는 것은 덤 |

**(c)를 고른다.** 낱개 풀이는 지금처럼 HTML로 두고 필기는 회차에만 넣는다.
실제 시험처럼 푸는 자리가 회차이므로 필기가 필요한 곳도 거기다.

## 2. 이미 절반은 되어 있다

`layout.py` 가 헤드리스 Chrome으로 블록 높이를 실측하고 면을 배정한다.
빌드 로그가 그 결과를 이미 찍는다.

```
p 3(R)  953px  97% ███████████████████  0,1,2,3,4
p 4(L)  785px  80% ████████████████     5,6
```

`contentBounds` 에 더 필요한 것은 **블록 안의 문항별 y 범위**뿐이다.
측정 스크립트는 있고 대상만 블록에서 문항으로 넓히면 된다.

그리고 **문제집 PDF 다섯 회차 합계가 4.6MB다.** PSAT 앱이 회차당 3~5MB인 것과
견주면 아주 작다. 원격 배포 없이 **APK에 그냥 넣어도 된다**(현재 55MB).

## 3. 저장소를 CRUD로 — 물어보신 것

**결론: 이점이 있다. 그리고 필기를 넣을 거라면 선택이 아니라 전제다.**

### 지금 무엇이 문제인가

`lib/store.dart` 를 보면 이렇게 되어 있다.

```dart
// 2행   SharedPreferences 에 JSON 문자열 하나로 저장한다
// 112행 _prefs.setString(_key, jsonEncode(encodeStore(snapshot())))
```

**한 문항을 풀 때마다 기록 전체를 다시 직렬화해 통째로 덮어쓴다.**
이미 이 값이 부담이라 95행에 `saveSoon()` 600ms 디바운스를 넣어 두었다.
그것은 고친 것이 아니라 미뤄 둔 것이다.

읽기도 마찬가지다. 오답·복습·통계가 전부 전 문항 순회다.

| 위치 | 하는 일 |
|---|---|
| `store.dart:162` | 복습 대상 — `allIds.where(...)` |
| `store.dart:171` | 전 문항 훑기 |
| `store.dart:185` | 시도 기록 이중 순회 |
| `store.dart:250` | 북마크 — `mark.entries.where(...)` |

540문항이고 시도는 쌓이기만 한다. 아직 견디는 이유는 데이터가 작아서다.

### 필기를 넣으면 확실히 터진다

PDF 한 쪽에 밑줄 몇 개를 그으면 획 좌표가 수십 KB다. 회차 하나가 13~32쪽이니
**한 회차 필기가 수백 KB에서 MB**가 된다. 이것을 한 칸 JSON에 넣으면 문항을
하나 풀 때마다 그 전부를 다시 쓴다. 못 쓴다.

### 그래서 어떻게 하나 — 스키마가 아니라 계층만 바꾼다

**가장 큰 값은 웹판과의 1:1 대응이다.** `README` 가 「저장 형식·SM-2 간격·검색
로직을 웹앱과 1:1로 맞췄다」고 못박고 있고, 한쪽을 고치면 다른 쪽도 고치는 것이
규칙이다. 웹판은 `localStorage` 라 `sqflite` 가 없다.

그래서 **바꾸는 것은 물리 저장소뿐이다.**

```
지금   Store ──jsonEncode 전체──> SharedPreferences 한 칸
바꾼 뒤 Store ──행 단위 UPDATE──> sqflite
        └ snapshot()/encodeStore() 는 그대로 둔다 (백업·웹판 호환)
```

- `Store` 가 밖으로 내주는 모양(`att`·`srs`·`exams`·`sit`·`mark`)은 **손대지 않는다**
- `backup.dart` 의 내보내기·가져오기 JSON도 **그대로 둔다** — 웹판과 주고받는 형식이다
- 웹판은 아무것도 안 바뀐다. **논리 1:1은 유지되고 물리 저장만 갈린다**

### 얻는 것

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 한 문항 채점 | 기록 전체 재직렬화 | 그 행만 `UPDATE` |
| 복습 대상 | 전 문항 순회 | `WHERE due <= ?` + 인덱스 |
| 오답노트 | 전 문항 순회 | `WHERE last_correct = 0` |
| 통계 | 시도 이중 순회 | `GROUP BY` |
| 필기 | 넣을 자리가 없다 | 페이지 단위 행 |
| 백업 | JSON 만들기 | 그대로 (형식 유지) |

### 치를 값

- **마이그레이션 한 번**. 기존 `ncsbank.v1` 한 칸을 읽어 테이블로 옮기고,
  옮긴 뒤에도 **원본을 지우지 않는다**(되돌릴 자리)
- 실패하면 예전 경로로 떨어지게 둔다. 첫 배포는 두 경로가 함께 산다
- `sqflite` 하나 늘어난다

## 4. 수익화 — 무엇이 따라오나

물어보신 대로 **코드는 적고 코드 아닌 것이 많다.** 그래서 보류를 권한다.

### 광고 (`google_mobile_ads`)

| 필요한 것 | 코드인가 |
|---|---|
| AdMob 계정 · 앱 등록 · 광고 단위 발급 | 아니다 |
| **개인정보처리방침 URL** — 스토어와 AdMob 양쪽 필수 | 아니다 |
| Play 콘솔 「데이터 안전」에 광고 ID 수집 신고 | 아니다 |
| 아동 대상 여부 신고 | 아니다 |
| EU 대상이면 UMP 동의 양식 | 반반 |
| iOS면 ATT 팝업 | 반반 |
| 배너·전면 광고 붙이기 | 코드 (작다) |

### 구독 (RevenueCat 또는 `in_app_purchase`)

| 필요한 것 | 코드인가 |
|---|---|
| Play 결제 프로필 — **사업자 정보·세금 신고** | 아니다 |
| 구독 상품 등록 · 가격 · 기간 | 아니다 |
| 청약철회·전자상거래법 고지 (국내) | 아니다 |
| 해지 방법 화면 고지 (심사 항목) | 반반 |
| 영수증 검증 | RevenueCat이 대신한다 — 대신 **계정 의존이 생긴다** |
| 구매·복원 흐름 | 코드 (작다) |

### 그리고 원칙과 부딪힌다

이 앱은 **서버가 없다는 것이 성질**이다. 구독을 넣으면 「누가 구독자인가」를
물어야 하고, RevenueCat이 대신해 주더라도 **네트워크와 계정 의존**이 생긴다.
비행기 모드에서 전부 풀린다는 지금의 성질이 조건부가 된다.

> **권고 — 보류.** 붙이는 코드는 하루치지만 계정·법무·심사가 붙는다.
> 기능을 먼저 채우고, 배포 규모가 커진 뒤에 다시 본다.
> 그때 **광고만 먼저** 넣는 것이 구독보다 문턱이 훨씬 낮다.

## 6. 단계

### 1단계 — 알림·차트 (작고 서로 안 얽힌다)

**A. 복습 알림**
- `flutter_local_notifications` + `timezone`
- `srs` 의 `due` 가운데 가장 이른 것을 기준으로 하루 한 번 예약
- Android 13+ `POST_NOTIFICATIONS` 런타임 요청
- **정확 알람은 쓰지 않는다.** PSAT 앱은 `SCHEDULE_EXACT_ALARM` 을 넣었는데
  스토어가 사유를 요구한다. 복습이 분 단위로 정확할 이유가 없다
- 설정 화면에 시각 지정과 끄기
- **웹판에는 넣지 않는다.** PWA 알림은 iOS 제약이 커서 1:1 대응이 깨진다 —
  예외로 문서에 남긴다

**B. 통계 차트**
- `fl_chart` 하나
- 과목별 정답률 막대 · 최근 30일 추이 선
- `stats_screen.dart` 만 바뀐다

### 2단계 — 저장소 전환 (§3)

1. 테이블 넷 — `attempt` · `srs` · `exam_result` · `mark`. 응시 중(`sit`)은 한 건이라 그대로 둔다
2. `Store` 의 바깥 모양은 고정. 안쪽만 `sqflite` 로 교체
3. 첫 실행에 `ncsbank.v1` 한 칸을 읽어 옮긴다. **원본은 지우지 않는다**
4. 마이그레이션 실패 시 예전 경로로 떨어진다
5. `backup.dart` 의 JSON 형식 무변경 — 웹판과 주고받는 것이 깨지면 안 된다
6. 검증: 옮기기 전후로 `snapshot()` 결과가 같은지 대조하는 테스트

### 3단계 — 회차 PDF 모드

1. `layout.py` 의 측정 대상을 블록에서 **문항**으로 넓힌다
2. `build.py` 가 회차마다 `page_map.json` 을 함께 낸다

```json
{ "round": "r2_korail", "pageSize": {"width": 595, "height": 842},
  "questions": [ {"no": 1, "bounds": [{"page": 2, "x": 0, "y": 96, "w": 515, "h": 372}]} ] }
```

3. `tools/export_bank.py` 가 PDF와 `page_map.json` 을 앱 자산으로 복사
4. 앱은 **`pdfx`** 를 쓴다 — `flutter_pdfview`(PSAT 앱이 쓰는 것)는 네이티브 뷰라
   위에 캔버스를 얹기 어렵다. `pdfx` 는 페이지를 이미지로 렌더하므로 4단계가 자연스럽다
5. 회차 화면에 「PDF로 풀기」 전환
6. **검수 도구**: `page_map.json` 을 받아 PDF 위에 사각형을 그려 주는 스크립트.
   매핑이 맞는지는 사람이 봐야 한다

### 4단계 — 필기

- `perfect_freehand` (PSAT 앱과 같은 것). 필압은 있으면 쓰고 없으면 굵기 고정
- 도구 셋 — 연필 · 형광펜(곱하기 합성) · 지우개(획 단위)
- 저장: 2단계의 DB에 **페이지 단위 행**으로. 좌표는 **PDF 페이지 좌표**라
  화면 크기가 바뀌어도 그대로 다시 그려진다
- 되돌리기는 획 단위 스택
- 회차 제출 뒤에도 남긴다 — 복기할 때 본다

`flutter_local_notifications_windows` 가 `xml` 을 낮추고 그것이 `printing` 계열을

2단계 전에 폰에서 오답노트를 한 번 구워 봐야 한다.

## 7-A. 이 PC 에서 직접 굽는다 — 2026-08-15 확인

워크플로 주석은 개발 PC 에서 못 굽는 이유를 둘 든다. **이 PC 는 둘 다 해당이 없다.**

| 주석의 이유 | 이 PC |
|---|---|
| Smart App Control 이 `impellerc.exe` 를 막는다 | **꺼져 있다**(`VerifiedAndReputablePolicyState = 0`) |
| 사용자 이름에 한글이 들어 있다 | `jongwoo` — ASCII |

그래서 CI 와 같은 **Flutter 3.44.9** 를 `C:\src\flutter` 에 두고 `flutter analyze` 와
`dart run tool/check_*.dart` 를 여기서 돌린다. 태그를 밀 때까지 기다리지 않는다.

주석이 가리키는 것은 **메인 PC** 다. 그쪽 사정은 그대로이므로 워크플로 주석은
고치지 않았다. 대신 검사 job 을 떼어 **푸시·PR 마다** 돌게 했다 — 두 PC 어디서
작업하든 잘못된 코드가 태그까지 살아 있지 않게.

## 8. 위험한 곳 셋

| 곳 | 무엇이 | 대비 |
|---|---|---|
| 2단계 마이그레이션 | 기존 사용자 기록이 날아가면 되돌릴 수 없다 | 원본을 지우지 않는다 · 실패 시 예전 경로 · `snapshot()` 대조 테스트 |
| 3단계 문항 매핑 | 좌표가 한 문항이라도 어긋나면 엉뚱한 곳이 보인다 | 검수 스크립트로 전 문항 눈으로 확인 |
| 웹판과의 1:1 | 알림은 웹에 없고 필기는 회차에만 있다 | **예외를 `app/README.md` 에 적는다.** 규칙을 어기는 것이 아니라 범위를 좁히는 것이다 |

## 9. 하지 않기로 한 것을 적어 두는 이유

PSAT 앱은 **문항을 만들지 않는다.** 기출 PDF를 잘 보여 주는 서비스이고,
그래서 Firebase·광고·구독·CDN이 다 필요하다. 우리는 문항을 만드는 쪽이고
콘텐츠가 저장소 안에 있다.

**구조를 통째로 따라가면 우리가 가진 이점을 버린다.** 가져올 것은
「기출을 실제 시험처럼 다루는 방법」 — §6의 3·4단계다. 나머지는 그 앱이
서비스이기 때문에 필요한 것들이다.
