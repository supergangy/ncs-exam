## v1.5.1 — 2026-08-12

**41~45번의 가상 규정을 실제 법령으로 갈아끼웠다.** 사용자가 법제처 원문
(노인장기요양보험법 법률 제21690호 · 국민건강보험법 법률 제21065호)을 주었다.

후기의 9%가 실제 조문 적용형이었다 — 「제43조 부당이득」·「제66조 수급권」이
그대로 언급된다. 여태 조문을 지어낼 수 없어 가상 규정으로 두었던 자리다.

### 41~43 세트 — 노인장기요양보험법 제28조·제40조
가상으로 지어낸 구조가 **실제 조문에 그대로 있었다.**

- 제40조 제3항 제3호 — 「월 한도액을 초과하는 장기요양급여」는 **본인이 전부 부담**
- 제40조 제4항 — 「본인부담금의 **100분의 60의 범위에서** … 차등하여 감경」
- 제40조 제2항 — 의료급여 수급자는 본인부담금 면제

본인부담률(15%)·감경률(40%)·월 한도액은 법률이 **대통령령·고시에 위임**한
값이라 조문에 없다. 그래서 조문과 **자료를 따로 주고** 각주에 그 사실을 밝혔다.
실제 시험이 쓰는 방식이고, 어디까지가 법이고 어디부터가 고시인지 자체가
43번의 판단 지점이 되었다.

### 44번 — 국민건강보험법 제57조(부당이득의 징수)
다섯 선지를 제1·2·3·4·5항에 하나씩 걸었다. 「어느 항이 근거인가」를 찾는
문항이다. 제5항만 방향이 반대라는 것(징수가 아니라 **가입자에게 돌려주는** 조항)이
정답 자리다.

### 45번 — 노인장기요양보험법 제19조·제43조·제66조
네 선지를 조문 그대로 두고 하나만 숫자를 바꿨다(유효기간 「최소 1년 이상」 →
「6개월」). 조문형에서 가장 흔한 출제 방식이다.

### 검증
- **인용한 조문 16건을 원문과 기계로 대조했다. 어긋남 0.**
  공백을 지우고 원문 전체에서 찾는 방식이라 한 글자만 달라도 걸린다
- `selfcheck` 치명 0 · 경고 0 · `verify.py` 12건 불일치 0
- 정답 분포·세트 비율은 그대로다(각 12개 · 55%)

### 도구
`selfcheck` 의 문장 길이 검사(상한 100자)에서 **조문 인용 자료를 뺐다.**
조문은 한 문장이 길다 — 상한에 맞추려면 줄여야 하는데 줄이면 인용이 아니게
되고 문항의 근거가 사라진다. 「제N조(제목)」 꼴이 있으면 인용으로 본다.

### 의사소통 20문항
후기가 지문을 두고 「엄청 길고 뚱뚱해서 찾는 데 시간이 많이 걸림」이라 했다.
700~900자 지문 넷(학교폭력 · 반려동물 · 무역수지 · AI)을 문단 여럿으로 쪼개
근거를 흩어 두었다. **선지는 지문 표현을 그대로 쓰지 않았다** — 전부 유사 의미로
바꿔 적었다. 「지문에서 선지를 못 찾는다」가 이 시험의 성격이다.

### 수리 20문항
후기 소재를 문구까지 가져왔다.

- 「**100분의 몇**」 — 후기에 적힌 그대로다
- 「원모양 비율들 많았음(**비율 표시x**)」 — 수치 없는 원그래프를 그려 표를 봐야 풀린다
- 「**계산 회피 판단이 핵심**」 — 계가 1,000이라 나눗셈이 필요 없는 표, 경계에 붙인
  선지 넷과 한눈에 보이는 하나, 「단순평균보다 낮다」만 알면 셋이 지워지는 문항

### 문제해결 20문항
규정적용 8 · 조건추론 7 · 모듈 5. 한도 초과분에만 다른 율을 적용하는 구조,
「100분의 40을 **감경**」과 「100분의 40**으로 한다**」의 차이, 가산 중복 불가,
경계값 60점, 나이에 따라 완화되는 요건을 다뤘다.

**규정은 전부 가상이다.** 실제 법령의 조문 번호와 문구는 쓰지 않았다.

### 쓰면서 잡은 결함 셋
- 순회 조건의 **해가 둘**이었다 — 120가지 순열을 전수로 돌려 유일해로 고쳤다
- 1인당 급여액이 **공동 1위**여서 정답이 둘이었다. 값을 바꾸니 총액 1위와
  1인당 1위가 갈리는 더 나은 함정이 됐다
- 원가·할인 문항의 **이익이 마이너스**였다

### 검증
- `selfcheck` 치명 0 · 경고 0. 정답 ①~⑤ **각 12개** · 세트 33/60(55%) · 각주 4개
- `rounds/r5_nhis/verify.py` 신설 — 계산형 **13건의 답을 독립적으로 다시 구해** 대조.
  불일치 0. **회차 문항을 기계 검증한 것은 이번이 처음이다**
  (`tools/verify_ncs.py` 는 `ncs-*` 공통 문항 139건만 다룬다)

### 설계 정정
`<보기>` 조합형 목표를 10 → **3문항**으로 고쳤다. 처음의 10은
`CORPUS_ANALYSIS.md:185` 의 「정보 47% · 한전 27% → **정보·기술 영역에 집중 배치**」

가중평균 · 지수 · 누적 · 단위(천 명) · 각주 정의 · 순위 변동 · **%p와 %의 구분** ·

### 규정적용 20문항
코레일 최대 격차였다(후기 28% 대 은행 13%). 후기 소재가 아주 구체적이다 —
「부가운임 30배」가 표현만 달리해 **열네 번** 되풀이되고, 정기승차권 금액과
성인·학생 할인율 차이가 있다.

약관·행동강령·위임전결규정·매뉴얼·여비규정을 다뤘다. 배수를 가르는 요건, 본문과 단서,
「미만」과 「이하」의 경계, 전결의 분할 금지와 대결, 예외가 금액표를 덮는 구조,
규정이 다른 규정을 가리킬 때 따라가는 것.

**실제 법령의 조문 번호와 문구는 쓰지 않는다.** 전부 가상 규정이고 판정 근거를
지문 안에 두었다. 규정적용 능력은 규정을 읽어 사례에 맞대는 힘이므로 규정이 가상이어도
묻는 것은 같다.

### 유형 목록이 쓸모 있어졌다
표기가 갈린 16곳을 통일했다(`조건추리`/`조건추론` 은 12문항이 5개 라벨로 쪼개져 있었다).

전에는 127종 가운데 67종(53%)이 1문항짜리였다.

사전에 없는 유형이면 내보내기가 멈춘다(`bank/types.py`). 이 가드가 이번에 새 유형
8종을 즉시 잡아냈다.

## v1.3.0 — 2026-08-10

### 오답노트 PDF 를 폰에서 바로 만든다

이때까지 「PDF 용으로 내보내기」는 **문항 번호만 담긴 `.json`** 을 냈고, 진짜 PDF 는
PC 에서 `python tools/wrongnote_pdf.py` 를 돌려야 나왔다. 버튼 이름이 오해를 샀다.

이제 **「PDF 만들기」** 를 누르면 앱이 인쇄 시트를 띄운다 — 거기서 「PDF 로 저장」·
공유·인쇄를 고른다. 문제와 해설이 함께 실리고, **내가 고른 답까지 빨갛게** 표시된다
(PC 판에는 없는 것이다. 오답노트에는 이게 있어야 한다).

구현 — 문항이 이미 HTML 이라 안드로이드 시스템 WebView 에 그대로 물린다
(`printing` 의 `convertHtml`). 표와 인라인 SVG 가 앱 화면(`flutter_html`)보다
오히려 정확히 나온다. 서식은 `templates/solution.html.j2` 를 따라가 A4·9.6pt 로 맞췄다.

`convertHtml` 은 deprecated 지만 안드로이드 구현(WebView + PrintDocumentAdapter)이
멀쩡히 살아 있다. 위젯으로 다시 짜면 표·SVG 를 손수 구현해야 하고 결과도 못하다.

기존 `.json` 내보내기는 **「PC용 목록 내보내기」** 로 이름을 바꿔 남겼다 —
표지·쪽번호·빠른정답이 붙는 제대로 된 인쇄본은 여전히 PC 쪽이 낫다.

### 고침
- 선지 단평 2건에 마크다운 별표(`**굵게**`)가 그대로 새어 나왔다
  (`r4_korail-12`·`-15`). **앱과 PC PDF 양쪽에** 나오던 것이라 원본을 고쳤다

### 검증
`lib/note_html.dart` 는 Flutter 를 쓰지 않는다 — `dart run tool/check_note_html.dart`
로 인쇄본을 뽑아 **브라우저에서 실제 모양을 눈으로** 봤다. 앱도 같은 HTML 을 쓰므로
거기서 본 것이 곧 PDF 다. 표 9개·SVG 2개·밑줄 10곳·윗첨자 22곳이 살아 있고,
A4 인쇄 폭(688px)을 넘는 표·그림이 없음을 확인했다(가장 넓은 표 546px).

## v1.2.0 — 2026-08-07

오래 쓰기 위한 것들. 여섯 가지.

### 기록 백업·복원
폰을 바꾸면 푼 기록이 전부 날아가던 것. 설정 › 기록에서 `.json` 한 장으로 내보내고
새 기기에서 불러온다. **통째로 덮어쓴다** — 확인창에 백업과 지금 기록의 건수를
나란히 보여 주고, 덮어쓰기 직전 지금 것을 `ncsbank.v1.prev` 로 남긴다.

`share_plus` 는 내보내기 전용이라 되돌려 받을 길이 없었다 → `file_picker` 를 넣었다.

### 글자 크기
설정에 다섯 단계(0.9 / 1.0 / 1.15 / 1.3 / 1.5). 고르는 즉시 미리보기에 반영된다.
`MediaQuery` 로 걸어 문제·지문·해설(`flutter_html`)까지 함께 커진다.

### 앱 아이콘
Flutter 기본 「F」를 웹판과 같은 도안으로 바꿨다. adaptive 아이콘까지 만들어
Android 8+ 에서 기기 모양대로 깎인다(전에는 정사각이 흰 테두리째 우겨넣어졌다).
`tools/make_icons.py` 가 Pillow 로 그린다 — 손으로 만든 PNG 는 근거가 없다.

### 풀던 자리 이어하기
50문항 세트를 나갔다 오면 1번부터이던 것. `Store.solo` 한 칸에 남기고, 홈에
이어하기 카드를 띄운다. **같은 묶음으로 다시 들어와도** 저장된 순서·채점 상태로 잇는다
(문항 집합으로 견주므로 섞여 들어와도 알아본다). 낱개 1문항은 저장하지 않는다.

### 문항별 소요 시간
`Attempt.ms` 신설. 낱개 풀이에서 쪽이 보인 순간부터 채점까지를 잰다.
**10분을 넘으면 안 센다** — 켜 둔 채 자리를 비운 것이지 푼 것이 아니다.
통계에 평균 풀이 시간 KPI, 과목 줄마다 평균. 회차 응시는 채점 순간이 없어 재지 않는다.

### 목록 필터
과목·직렬 화면 위에 칩 네 개 — 전체 / 안 푼 것 / 틀린 것 / 북마크. 각 칩에 걸리는
문항 수가 함께 나온다. 「이어서 풀기」와 유형별 줄에 같이 걸린다.
세 파일에 복붙돼 있던 「안 푼 것 먼저」 로직을 `lib/pool_filter.dart` 로 모았다.

### 안에서 바뀐 것
- 직렬화를 `lib/backup.dart` 로 뗐다 — Flutter 를 안 써야 `dart run` 으로 검증한다
- `mobile/windows/` 삭제. 안 쓰는 데스크톱 타깃인데 플러그인 심볼릭 링크 때문에
  Windows 개발자 모드 없이는 빌드가 막혔다. 이 앱은 안드로이드 전용이다

커밋은 태그 `v1.2.0` 참조

- 낱개 풀이에서 되돌아가도 채점 상태가 남는다 (전에는 앞으로만)
- 하단 탭에 복습·오답 배지, 홈에 검색 버튼, 진행 중 회차의 남은 시간
- 지난 성적을 눌러 결과를 다시 본다

### 고침 — 문항이 안 보이던 것
- **표 402개가 통째로 안 그려졌다.** `flutter_html` 3.x 는 `<table>` 을 스스로
  그리지 않는다 — `flutter_html_table` 의 `TableHtmlExtension` 을 붙여야 하고,
  없으면 오류 없이 조용히 사라진다. 자료·지문에 표가 있는 78문항이 풀 수 없는 상태였다
- **발문·선지를 정규식으로 벗기고 있었다.** `&lt;보기&gt;` 가 그대로 노출됐고,
  `cm<sup>2</sup>` 가 `cm 2` 가 됐고(값이 바뀐다), 선지 182곳의 밑줄이 사라져
  어문규범 문항이 무엇을 묻는지 알 수 없었다 → `lib/text.dart` · `HtmlText`
- 같은 이중 이스케이프가 웹판 발문·선지단평에도 있어 함께 고쳤다 (`app/app.js`)

### 고침 — 그 밖
- 탭 다섯 개가 부팅 때 숫자에 얼어붙어 있었다 (`IndexedStack` + `const` 목록)
  → `Store` 를 `ChangeNotifier` 로
- 제출 확인창 위에 자동 제출이 겹치면 앱이 멎었다
- 스와이프 중 별표가 옆 문항에 붙었다
- 메모를 한 번 쓰면 지울 길이 없었다
- 깨진 기록을 반만 읽고 덮어써 나머지를 영영 잃었다
- 회차가 사라진 뒤 그 태그로 들어가면 켤 때마다 죽었다
- 백그라운드 6시간 뒤 60분 시험에 「360분 소요」가 찍혔다
- SVG 가 화면 폭에 안 맞았다 · 과목 「전체 풀기」가 맞힌 문제를 다시 냈다
