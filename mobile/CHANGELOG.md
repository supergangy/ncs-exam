# 변경 이력 — NCS PASS 앱

APK 는 GitHub Releases 에 버전별로 올린다 (`gh release list`).
저장소에 커밋하지 않는다 — 55MB 짜리가 판올림마다 히스토리에 영구히 쌓인다.

```bash
python mobile/tool/build_apk.py                       # APK 를 짓는다
gh release create v1.2.0 <apk> --title "..." --notes-file <노트>
```

**`flutter build apk` 를 저장소에서 바로 돌리지 마라.** 경로에 한글(`사용자`)이
들어 있어 Flutter 3.44 의 AOT 스냅샷터가 그것을 깨뜨린다 — 커널 컴파일까지는
되는데 그 결과(`app.dill`)를 못 읽는다. 파일이 없는 게 아니라 이름이 깨진 것이다.
`build_apk.py` 가 ASCII 경로(`C:/dev/ncs_bank`)에 사본을 두고 지어 결과만 가져온다.
같은 이유로 `flutter analyze` 도 LSP 핸드셰이크에서 죽는다 — 앱 검사는
`tool/check_*.dart` 를 쓴다.

## v1.13.0 — 2026-08-28

**전산직에도 회차가 생겼다.**

전산직 문항은 **300건 있는데 회차가 0개**였다. 앱을 열면 낱개 연습만 있고
시간 재고 앉을 자리가 없었다. NCS 는 여섯 회차인데 전산직은 하나도 없었다.

전산 전공 **40문항 / 50분** 한 벌을 넣었다 — 8과목.

| 과목 | 문항 | | 과목 | 문항 |
|---|---:|---|---|---:|
| 네트워크 | 8 | | 운영체제 | 4 |
| 데이터베이스론 | 8 | | 소프트웨어공학 | 4 |
| 프로그래밍언어 | 7 | | 전자계산기구조 | 2 |
| 정보보안 | 5 | | 데이터통신 | 2 |

### 왜 전공만인가

전산직 후기 153건이 말하는 시험은 **두 교시**다 — 한국부동산원 「1교시 NCS /
2교시 전공」, 대구교통공사 「NCS 40 + 전산학개론」, 인천시설공단 「전산학개론 단독」.
NCS 교시는 이미 여섯 벌이 있으므로 비어 있는 전공 쪽을 채웠다.
타협이 아니라 시험이 실제로 그 모양이다.

### 배분은 후기가 정했다

과목을 가르는 어휘가 걸린 후기 건수를 세고 최대잔여법으로 40을 나눴다.
바닥은 2 — 한 과목이 1문항만 나오면 있으나 마나다.

**첫 셈은 버렸다.** 「프로그래밍언어 61건」이 나왔는데 `코드`·`Java` 같은 넓은
낱말이 다른 과목의 후기까지 끌어온 것이었다(`types: ['코드']` 47건이 통째로 섞였다).
과목을 실제로 가르는 어휘만 남겨 다시 세니 26건이다.

### 40문항 중 34문항의 답을 코드가 다시 구한다

전산 전공은 정답이 **지문 밖 사실**로 정해진다. 틀리면 막을 수단이 계산밖에 없다.
SQL 은 sqlite 로 돌리고, 정규형은 폐포로 후보키를 구해 판정하고, 스케줄러·클럭·
은행원 알고리즘·CBC 오류 전파는 실제로 굴린다. **확인 34건 · 어긋남 0건.**

남은 여섯은 계산으로 확정되지 않는 것이다 — 표준 4(캡슐화 · DHCP 포트 ·
UML · 자바 생성자 순서) · 개념 2(전자봉투 · 웹취약점 대책).
`verify.py` 가 그 여섯을 **이름을 대고 보고한다.** 목록에 없는데 검증기도 없는
문항이 생기면 그 자리에서 실패한다.

### 회차 목록이 직렬로 묶인다

일곱을 한 줄로 세우면 전산직 응시자가 NCS 여섯 개를 헤치고 자기 것을 찾아야 하고,
사무직 응시자는 전산 회차를 자기 시험인 줄 알고 연다. 홈의 과목 목록과 같은 규율로
묶었다 — **고르는 것이 아니라 묶는 것이다.**

회차의 직렬은 **문항이 정한다.** 내보내기가 과목에서 끌어낸다 — 그동안 회차 문항의
직렬은 `"ncs"` 로 못 박혀 있었고, 이 회차가 처음 그 가정을 깼다.
한 회차가 두 직렬에 걸치면 양쪽 묶음에 다 선다.

규칙은 `lib/tracks.dart` 에 **Flutter 없이** 둔다. `tool/check_tracks.dart` 16건.

## v1.8.0 — 2026-08-16

**회차 PDF 위에 직접 쓴다.** `PLAN.md` 4단계다.

### 필기

「PDF로 풀기」를 켜면 아래에 도구 막대가 나온다 — **연필 · 형광펜 · 지우개**,

- **형광펜** 은 굵기를 고정하고 반투명으로 얹는다. 획이 겹쳐도 색이 쌓이지
  않게 층을 따로 떠서 한 번에 올린다 — 밑줄을 두 번 그어도 같은 색이다
- **지우개** 는 획 단위다. 지나간 자리의 획 하나씩 사라진다
- 도구를 켜면 좌우로 안 넘어간다. 획을 긋다 화면이 넘어가면 그 획이
  통째로 날아가기 때문이다. 같은 도구를 다시 누르면 꺼지고 넘길 수 있다

### 좌표를 PDF 페이지 점으로 둔다

화면 폭은 회전·분할화면·기기마다 다르다. **화면 좌표로 저장하면 다음에 열 때
획이 딴 데 찍힌다.** 그래서 종이에 매인 값(PDF 페이지 점)으로 저장하고,
그릴 때 화면 폭에 맞춰 되편다. 굵기도 같은 이유로 페이지 점이다 —
화면 픽셀로 두면 큰 화면에서 가늘어진다.

`dart run tool/check_ink.dart` 가 **왕복이 제자리인지**와 **폭 360 과 1024 에서

### 제출한 뒤에도 남는다

결과 화면에 **「필기 다시 보기」** 가 생겼다. 회차를 내도 필기는 지우지 않는다 —
남겨 둔 뜻이 있으려면 볼 자리가 있어야 한다. 거기서는 **그려지지 않는다.**
채점이 끝난 답안을 나중에 고쳐 그리면 「그때 무엇을 생각했나」가 흐려진다.

### 저장

DB 판을 **2** 로 올리고 `ink` 테이블을 더했다 — `(회차, 쪽)` 이 열쇠인
**페이지 단위 행**이다. 한 쪽만 고쳐도 그 행만 다시 쓴다. 한 회차 필기가
MB 라 한 칸에 담으면 회차를 열 때마다 통째로 끌고 다니게 된다.

**백업 JSON 에는 넣지 않는다.** 웹판에 필기가 없어 1:1 이 깨지고, 크기도
기록의 수십 배다. 기기에만 남는 것으로 둔다 — `app/README.md` 의 예외 목록에
적었다.

화면을 나갈 때도 한 번 더 쓴다.

### 펜 태블릿을 앞에 두고 맞춘 것

주 무대가 펜 달린 태블릿이라 넷을 고쳤다.

- **팜 리젝션.** 펜이 한 번이라도 닿은 기기에서는 손가락을 그리기에서 뺀다.
  안 그러면 글씨를 쓸 때마다 손바닥 자국이 그려진다. 대신 손가락은
  **화면을 넘기는 데** 쓴다 — 펜으로 쓰면서 손가락으로 넘기는 것이
  태블릿에서 자연스럽다. 펜이 없는 폰에서는 손가락이 곧 붓이므로
  그때만 손가락을 받고, 도구를 켠 동안 화면을 잠근다
- **뒤집은 펜은 지우개.** S펜·서피스펜을 뒤집으면 도구와 상관없이 지운다
- **실제 필압을 쓴다.** 필압이 진짜인 획에서는 속도로 굵기를 흉내 내던 것을
  끈다 — 켜 둔 채로 두면 두 굵기가 겹쳐 획이 울퉁불퉁해진다. 획의 필압 값이
  다 같은지로 갈라내므로 저장 형식은 그대로다
- **종이 폭에 상한(900).** 태블릿에서 화면 폭을 다 쓰면 종이가 실물보다 두 배
  넘게 커진다. 상한에서 멈추고 가운데에 둔다

도구 막대가 지금 무엇으로 쓰는지 알려 준다 — 「펜으로 씁니다 · 손가락은
넘기기」. 손가락이 안 먹히는 것을 고장으로 오해하지 않게.
